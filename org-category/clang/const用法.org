* const修饰
** 给你一个最终简化模型（建议记这个）
#+begin_src  C
你只记这三种就够了：
const char *p;        // 常用（字符串、Flash）
char * const p;       // 很少用
const char * const p; // 配置表、查表
如果你愿意，我可以把这个再延伸到：
const + 函数参数（接口设计）
const 在结构体里的用法（非常实战，嵌入式常见）
这两个才是真正拉开水平的地方。
#+end_src
** 不用死记，给你一个工程上可执行的记忆法，核心是两条规则 + 一个读法。
*** 一、唯一规则（最重要）
#+begin_example
const 修饰它左边的东西；如果左边没有，就修饰右边
#+end_example
*** 二、用这个规则逐个拆
1️⃣
const char *p;
读： const 左边没有 → 修饰右边 char      ⇒ char 是 const
结论：
数据不能改
指针能改
2️⃣
char * const p;
读： const 左边是 *    ⇒ 指针是 const
结论：
指针不能改
数据能改
3️⃣
const char * const p;
拆两次：
第一个 const → 修饰 char
第二个 const → 修饰 *
结论：
都不能改
*** 三、更强记忆法（推荐你用这个）
#+begin_src C
  把声明从变量名开始读（非常关键，很多老工程师都这么用）：
  示例1
  const char *p;
  从 p 开始读：
  p 是一个 → 指针 → 指向 const char

  示例2
  char * const p;
  从 p 开始读：
  p 是一个 → const 指针 → 指向 char

  示例3
  const char * const p;
  p 是一个 → const 指针 → 指向 const char
#+end_src
*** 四、快速判断口诀（你可以直接用）
 左边有 const → 指针不能改
 右边有 const → 数据不能改
*** 五、你现在这个场景对应哪种？
const char *str;
属于：
数据只读（通常在 Flash）
指针可变
所以：
str = "abc";    // ✔
str = "xyz";    // ✔
str[0] = 'A';   // ❌（嵌入式可能直接炸）
*** 六、为什么要这么设计（给你工程理解）
这是为了区分两件完全不同的东西：
地址能不能变
地址里的内容能不能改
在嵌入式里非常关键：
Flash → 只能读 → const char *
RAM buffer → 可写 → char *
