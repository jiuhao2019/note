  ✅ 为什么使用 static inline

  1. 内联（inline）的作用

     编译器会尝试将函数体“展开”到调用处，避免函数调用开销（如压栈、跳转、返回）。

     对于小函数（如字节数组与 float/double 转换），展开后的效率更高，代码更紧凑。

  2. 静态（static）的作用

     限定作用域为当前编译单元（通常是包含这个头文件的 .c 文件）。

     防止多个 .c 文件同时包含这个头文件时，发生链接重复定义错误（multiple definition）。

  3. 适合放在头文件中

     正常的 inline 函数如果放在头文件中，多处调用可能引起链接冲突。

     加上 static 后，编译器每次都生成本地版本，不冲突。

     因此：
     ✅ static inline 是头文件中函数定义的推荐写法。

  ✅ 使用时机
  场景 是否推荐使用 static inline
  简单的工具函数（如 float ↔ byte） ✅ 推荐
  只在一个源文件中使用的函数 可选（static 即可）
  函数体复杂、可能多次调用 ❌ 不建议 inline，可能增加代码体积
  需要跨文件使用的库函数 ❌ 不应用 static，应在 .c/.h 拆分实现

  🧠 原因解释：

      static inline 的含义是：

          inline：编译器尽量内联展开；

          static：函数具有内部链接性，不会暴露到其他编译单元；

      如果多个 .c 文件都 include 这个头文件，每个编译单元都会有一份副本，即使函数内容相同。
