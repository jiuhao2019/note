qk模式 每个isr里都须加这？
#+end_src
* 需要加，而且是每个会与 QK 调度相关的 ISR 都必须加，否则行为不正确。
:PROPERTIES:
:CUSTOM_ID: f8e4bd7f-378d-4df8-aa51-2e58cae08f3a
:END:
#+begin_example
具体原则：


必须加的情况
只要该 ISR 内做了以下任一操作，就必须配对调用：


发布事件（QACTIVE_POST() / QF_PUBLISH()）


解锁/释放资源可能唤醒任务


调用任何 QP/QK 内核 API


这些操作可能触发调度，QK 需要知道：


你进入了 ISR（禁止调度嵌套错误）


你退出 ISR（在这里做调度决策）




可以不加的情况
如果 ISR 完全不涉及 QP/QK，例如：


纯硬件寄存器处理


只做标志位，不唤醒任务
那可以不加（但一般不建议混用风格）




为什么必须
QK 是抢占式内核（non-preemptive kernel with preemption points），调度点包括：


ISR 退出


内核 API 调用点


QK_ISR_EXIT() 内部会触发类似：


检查是否有更高优先级任务 ready


进行一次调度


不加的后果：


任务不会被及时调度（系统“卡住”）


优先级反转/延迟


行为不确定




标准写法


void USART1_IRQHandler(void){    QK_ISR_ENTRY();    // ISR 内容    QACTIVE_POST(...);    QK_ISR_EXIT();}


注意


必须成对出现


不要在 ISR 中间 return（否则 exit 不执行）


嵌套中断时也依赖它维护状态





结论：
只要 ISR 触及 QP/QK，就必须加；工程上通常统一“所有 ISR 都加”，最安全。
#+end_example
