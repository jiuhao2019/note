* git status 提示 ahead by 1 commit，但是git push 提示 冲突
#+begin_example
这种情况本质是：本地分支“领先”，但远端也发生了变化 → 分叉（diverged）了。
也就是说不是单纯的 “ahead”，而是：

你本地：+1 commit
远端：也有你没有的 commit
→ Git 无法 fast-forward，push 被拒绝
#+end_example

** git pull --rebase 的作用可以精确定义为：
:PROPERTIES:
:CUSTOM_ID: 26293f27-17a3-481a-9438-505b97fc9aec
:END:
#+begin_example
先获取远端更新，然后把“你本地的提交”移动（重放）到最新远端提交之后，使历史保持线性。
git pull --rebase 本质就是：
把你的提交“挪到别人提交后面”，而不是“合并在一起”。
#+end_example

* git stash
:PROPERTIES:
:CUSTOM_ID: 975702f2-68f0-41e7-bafe-07a5ec2d70af
:END:
#+begin_example
git stash 是一个非常有用的 Git 命令，用于临时保存工作目录的修改，以便切换分支或执行其他操作，而不必提交未完成的工作。

基本用法
1. 保存当前修改
bash
git stash
# 或
git stash save "可选描述信息"
将工作目录和暂存区的修改保存到存储栈中，并恢复干净的工作目录。

2. 查看存储列表
bash
git stash list
显示所有存储条目，格式：stash@{0}: 分支: 描述

3. 恢复最近存储
bash
git stash pop
# 恢复并删除该存储（默认最近一个）
或

bash
git stash apply
# 恢复但不删除存储
4. 删除存储
bash
git stash drop stash@{n}
# 删除特定存储
git stash clear
# 删除所有存储
常用选项
只存储暂存区的修改
bash
git stash --keep-index
包含未跟踪的文件
bash
git stash -u
# 或
git stash --include-untracked
包含所有文件（包括忽略的）
bash
git stash -a
# 或
git stash --all
恢复特定存储
bash
git stash pop stash@{2}
git stash apply stash@{1}
实际应用场景
场景1：临时切换分支
bash
# 当前有未提交的修改
git stash
git checkout other-branch
# 处理其他事情...
git checkout original-branch
git stash pop
场景2：测试干净代码
bash
git stash
# 运行测试
git stash pop
场景3：存储并创建分支
bash
git stash branch new-feature
# 基于存储创建新分支并自动应用存储
高级用法
查看存储内容
bash
git stash show stash@{0}
git stash show -p stash@{1}
# -p 查看详细差异
部分存储
bash
# 交互式选择要存储的修改
git stash -p
创建存储但不保存
bash
git stash create
# 创建存储对象但不从工作区删除
示例工作流
bash
# 1. 开始新功能开发，有未完成的修改
$ git status

# 2. 紧急修复bug，需要切换分支
$ git stash -u
$ git checkout main
$ git checkout -b hotfix-123

# 3. 修复完成后返回
$ git checkout feature-branch
$ git stash pop

# 4. 如果存在冲突，需要解决冲突
# 5. 完成后清理存储
$ git stash drop stash@{0}
注意事项
存储的是修改，不是文件本身

默认不存储未跟踪文件，使用 -u 选项

pop 与 apply 的区别：pop 恢复后删除存储

存储基于提交，所以可以跨分支应用

冲突可能发生在恢复时，需要手动解决

实用别名配置
bash
git config --global alias.st 'stash'
git config --global alias.sta 'stash apply'
git config --global alias.std 'stash drop'
git config --global alias.stl 'stash list'
git config --global alias.sts 'stash show -p'
记住：git stash 是你代码的临时保存点，不是永久解决方案，及时应用和清理存储可以保持工作区整洁。
#+end_example

#+begin_example
其实是：GitHub 主页面默认显示 main 分支的内容
你 push 到其他分支，比如 feature1，GitHub 提示 Compare & Pull Request
实际上代码已经推上分支去了。
这个提示没办法设置不 显示(如下两个方法都不能解决，只能侧面消炎)。
#+end_example
** 方法1  把该分支设为默认分支

#+begin_example
进入仓库 → Settings → Branches → Default branch
改为你要的分支，比如：dev
这样 push 到 dev 不会再提示你与 main 比较。
#+end_example
** 方法2 ✔ 让分支互相独立、互不干扰, 你可以新创建两个完全独立分支：
:PROPERTIES:
:CUSTOM_ID: d9192c3e-2bd0-4223-a459-bb7fd23626a7
:END:
#+begin_src  sh
git checkout --orphan branchA   创建新分支
git commit -m "init branchA"
git push origin branchA

git checkout --orphan branchB
git commit -m "init branchB"
git push origin branchB

--orphan 让每个分支没有共同历史，完全独立，相当于一个仓库里存两个项目
#+end_src
