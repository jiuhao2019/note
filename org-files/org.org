    If there is an active region, change that region to a new emphasis.
    If there is no region, just insert the marker characters and position the cursor between them.

* Category,即分类，一个属性,CATEGORY 更多用于 Agenda 分类显示和 Clock 时间统计
:PROPERTIES:
:CUSTOM_ID: 058f8890-a2ed-43b5-bf9f-312e8bbfe537
:END:
#+begin_example
在 Org Mode 中：
:CATEGORY: 列表
是一个属性（Property），用于给当前标题（或整个文件）指定分类名称（Category）。
例如：
,* TODO 学习数据结构
  :PROPERTIES:
  :CATEGORY: 学习
  :END:

,* TODO 修改驱动
  :PROPERTIES:
  :CATEGORY: 工作
  :END:

主要影响：
Agenda 显示
在 Agenda 中可以显示分类名：
Today:
  学习:     TODO 学习数据结构
  工作:     TODO 修改驱动
分类名通常显示在任务前面。

日志和时间统计
Clock Report、日志记录等功能中，可以按 Category 汇总：
Category    Time
----------------
学习        2:30
工作        1:45
Agenda 过滤
可以按 Category 过滤任务：
(org-agenda-filter-by-category "学习")
导出或 Lisp 代码处理
很多 Org API 会读取 CATEGORY 属性进行分类统计。
如果没有设置 CATEGORY：
,#+CATEGORY: 学习
则整个文件默认使用这个分类。
如果文件和标题都没设置，则默认使用文件名作为 Category。
例如：
notes.org
Agenda 中可能显示：
notes: TODO ...
所以 :CATEGORY: 本身不会改变标题显示效果，也不会影响折叠、排序等，主要是给 Agenda、Clock、统计报表等功能提供一个“分类标签”。
#+end_example

** 核心概念: 引用文档(Reference Doc)
:PROPERTIES:
:CUSTOM_ID: 9c532c18-5571-4ab9-8856-e194c5c8bdf8
:END:
Org Mode 导出 Word 文档的秘密武器是 Pandoc. Pandoc 在转换 Markdown/Org 文件到 DOCX 时, 不会凭空想象样式, 而是会参照一个现有的 Word 文档作为模板. 这个模板就是所谓的" 引用文档" . 你在这个模板里设置好" 正文" , "标题1" , " 代码块" 等样式的字体, 字号, 颜色等, Pandoc 就会把这些样式应用到最终导出的 Word 文档中.

** 第一步: 创建并定制你的引用文档
:PROPERTIES:
:CUSTOM_ID: bc00caf7-b11f-483d-8304-ab8fc2d3ebba
:END:
#+begin_example
生成一个默认模板: 如果你手头没有现成的 Word 模板, 可以先让 Pandoc 生成一个默认的. 打开终端, 输入:

pandoc -o my-template.docx --print-default-data-file reference.docx
这会在当前目录生成一个名为 my-template.docx 的文件.

用 Word 软件编辑 my-template.docx: 用 Microsoft Word 或 LibreOffice Writer 打开 my-template.docx.

核心操作: 修改" 样式" ! 在 Word 的" 主页" 选项卡下, 找到" 样式" 窗格. Pandoc 导出的内容会映射到这里已有的样式.
正文: 找到并右键点击 "Normal" 或 "Body Text" 样式, 选择" 修改..." . 在这里设置你希望的默认字体(如微软雅黑, 思源宋体), 字号(如小四, 10.5pt), 颜色和段落间距.
标题: 找到并修改 "Heading 1" , "Heading 2" 等样式, 设置各级标题的字体, 字号和颜色.
代码块: 找到并修改 **"Code" ** 或 "Source Code" 样式(通常是等宽字体), 设置代码的字体和字号.
其他如列表, 引用块等, Pandoc 也有对应的默认样式名.
务必保存: 修改完成后, 确保保存 my-template.docx 文件.
第二步: 在 Emacs Org Mode 中配置导出
推荐使用 Emacs 的 ox-pandoc 包, 它能让 Org Mode 无缝调用 Pandoc 进行导出.

安装 ox-pandoc: 如果尚未安装, 通过 MELPA 安装: M-x package-install RET ox-pandoc RET.

全局设置: 在 Emacs 配置中指定引用文档路径: 在你的 Emacs 配置文件(如 ~/.emacs.d/init.el)中加入:

(require 'ox-pandoc)
(setq org-pandoc-options
      '((docx . ((standalone . t)
                 ("reference-doc" . "/path/to/your/my-template.docx")))))
请将 "/path/to/your/my-template.docx" 替换为你实际的 my-template.docx 文件路径.

逐个文件设置:直接在 Org 文件头部指定(更灵活): 如果只想为某个特定的 Org 文件使用自定义模板, 可以在 Org 文件开头添加 PANDOC_OPTIONS 选项:

,#+TITLE: 我的定制文档
,#+AUTHOR: 你的名字
,#+PANDOC_OPTIONS: reference-doc:/path/to/your/my-template.docx
这种方式下, ox-pandoc 会自动读取并使用这个引用文档.

第三步: 导出你的 Word 文档
在 Org 文件中, 执行标准的导出命令:

C-c C-e (或 M-x org-export-dispatch)

如果导出后格式仍然不对, 最常见的问题是 my-template.docx 内部的样式设置有问题.

打开 my-template.docx 并手动测试样式:

如果手动应用后, 字体和颜色仍然不生效, 那说明你保存的 my-template.docx 文件本身有问题, 或者你修改的不是正确的样式. 请仔细检查并确保保存.
检查 Pandoc 日志: 你之前在 Emacs *Message* 缓冲区看到的 Pandoc 命令参数(例如 pandoc ... --reference-doc=/Users/.../my-template.docx ...)很重要. 这表明 Pandoc 确实接收到了引用文档参数. 如果格式未生效, 问题极大概率出在 my-template.docx 文件内部, 而不是 Pandoc 命令.

* org归档,一般是TODO完成后，确定不会再维护了，即可archived
#+begin_example
在列举的org tag界面 ，默认按键绑定 $ -> org-agenda-archive
也就是说，$ 并不是删除，而是归档（Archive）。
org-agenda-archive 的作用是：
将当前 Agenda 对应的 Org 条目移动到归档位置（通常是 xxx.org_archive 文件，或者你配置的归档位置）。
原文件中的该条目会被移走，因此 Agenda 会立即刷新，看起来像“删掉了”。
因此 Agenda 中这一行消失了，但实际上并没有删除，只是移动到了归档文件。
#+end_example
** 移动到归档文件是什么意思
#+begin_example
“移动到归档文件”在 org-mode 里指的是：把某个 Org 条目从当前 .org 文件中移走，保存到一个专门的归档文件中，而不是删除。

1. 归档文件是什么

默认情况下：
xxx.org          → 当前工作文件
xxx.org_archive  → 归档文件

归档文件是 Org 用来保存“历史完成/不再需要处理的内容”的地方。
#+end_example
** 本质行为
#+begin_example
归档 = 移动（move），不是复制，也不是删除：

从当前 buffer 删除该 subtree
写入 archive 文件
保留完整内容（包括子任务、属性、LOGBOOK 等）
#+end_example
** 为什么 Org 要这样设计
#+begin_example
因为 Org 强调“任务生命周期管理”：

TODO：进行中
DONE：已完成（仍留在原文件）
ARCHIVE：长期不需要，但保留历史记录

适合：
项目结束的任务
已完成但不想污染当前文件的内容
需要保留审计/记录
#+end_example
** 和删除的区别
       | 操作        | 是否保留 | 是否可恢复 | 作用       |
       |-------------+---------+----------+------------|
       | kill/delete | 否      | 否       | 真删       |
       | done        | 是      | 是       | 状态变化    |
       | archive     | 是      | 是       | 移到归档文件 |
** 归档位置可配置
#+begin_example
可以改为：

(setq org-archive-location "~/org/archive.org::")

或者按标题分文件、分树等。
org-archive-location 决定归档的“去向规则”，不仅仅是一个固定文件路径，它还可以控制如何归档（按文件 / 按标题 / 按层级）。
格式本质是： (setq org-archive-location "PATH::SCOPE")
#+end_example
*** 最基础：固定归档文件
#+begin_example
(setq org-archive-location "~/org/archive.org::")

含义：

所有归档内容 → archive.org
:: 后为空 → 使用默认“当前子树归档”

效果：

notes.org        -> archive.org
#+end_example
*** 按“当前文件”分文件归档（推荐常见）
#+begin_example
(setq org-archive-location "%s_archive.org::")

含义：

%s = 当前 org 文件名
每个文件有自己的 archive

例子：

project.org        -> project.org_archive
todo.org           -> todo.org_archive
#+end_example
*** 按标题分层归档（子树归档）

#+begin_example
默认 :: 表示：

:: = 当前条目整个 subtree

也可以指定层级：

(setq org-archive-location "%s_archive.org::* Archived Tasks")

含义：

归档到指定标题 “Archived Tasks” 下面
所有归档条目集中在一个 heading

归档文件结构：
#+end_example

*** 按日期/路径分组（更高级）

#+begin_example
例如按月份：

(setq org-archive-location "%s_archive.org::datetree/")

或：

(setq org-archive-location "%s_archive.org::%s")

不同配置会影响插入位置策略。
#+end_example

*** 常见组合推荐
#+begin_example
(1) 每文件一个 archive（最常用）
(setq org-archive-location "%s_archive.org::")

优点：

清晰隔离项目
不会混乱
(2) 单一 archive 总库
(setq org-archive-location "~/org/archive.org::")

优点：

统一管理历史记录

缺点：

容易变大
(3) 集中 + 分类标题
(setq org-archive-location "~/org/archive.org::* %s")
#+end_example
** 归档行为本质
#+begin_example
无论哪种配置，核心逻辑都是：

从当前 buffer 移除 subtree
写入 archive file
保留完整结构（tags/properties/LOGBOOK）

如果你想进一步控制：

不移动，只标记
归档时压缩 subtree
自动归档 DONE

可以继续细化配置（org-archive-subtree / org-auto-archive）。
#+end_example
