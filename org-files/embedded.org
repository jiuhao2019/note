    在Linux驱动中，unlocked_ioctl是ioctl函数的一个替代实现。
    通常，ioctl用于处理设备文件的输入输出控制操作，但是在Linux 4.8及之后的版本中，内核对ioctl进行了改进，
    引入了unlocked_ioctl，使得设备驱动在处理ioctl请求时更加安全且不需要关心锁的管理。
    区别：
        传统的ioctl：需要显式地在内核代码中加锁，防止多个线程或进程并发访问设备资源。
        unlocked_ioctl：不再需要显式加锁，内核会自动处理对设备的同步。它可以在不需要锁定设备的情况下处理ioctl请求，这样可以减少锁的开销，提高并发性能。

#+begin_src
    在 Linux 内核中，中断处理可以分为 上半部（上文, Top Half） 和 下半部（下文, Bottom Half），
    这样可以提高系统的实时性和整体性能。
    1. 上半部（Top Half）
    作用：

        主要用于快速响应中断，尽快处理关键任务。
        运行在中断上下文（Interrupt Context），不能执行可能引起睡眠的操作（例如调用 schedule()）。

    主要特点：

        快速执行，只处理最关键的工作，比如读取寄存器、清除中断标志等。
        不能睡眠，因此不能进行涉及调度的操作（例如 kmalloc(GFP_KERNEL) 或 copy_to_user()）。
        通常是中断服务例程（ISR），即 irq_handler_t 类型的回调函数。

    典型代码示例：

    irqreturn_t my_irq_handler(int irq, void *dev_id) {
        // 处理最基本的中断逻辑，如读取硬件状态、清除中断标志
        printk(KERN_INFO "IRQ %d triggered\n", irq);

        // 触发下半部（如 tasklet 或 workqueue）
        tasklet_schedule(&my_tasklet);

        return IRQ_HANDLED; // 处理中断成功
    }

    2. 下半部（Bottom Half）
    作用：

        处理非紧急的中断任务，可以在内核的进程上下文运行，允许睡眠。
        适用于需要更多时间的任务，如数据传输、内存分配等。

    主要实现方式：

    Linux 提供了几种不同的机制来实现下半部：
    ① 软中断（SoftIRQ）

        适用于高吞吐量、高优先级任务（如网络、定时器）。

        在特定 CPU 上以高优先级执行，不受普通任务调度影响。

        由 do_softirq() 处理，不能直接睡眠。

        示例：

        DECLARE_TASKLET(my_tasklet, my_tasklet_function, 0);

        void my_tasklet_function(unsigned long data) {
            printk(KERN_INFO "Executing tasklet in bottom half\n");
        }

    ② 任务队列（Tasklet）

        任务执行时间短，可在任意 CPU 上运行。

        在软中断基础上封装，适用于轻量级任务。

        示例：

        void my_tasklet_func(unsigned long data) {
            printk(KERN_INFO "Tasklet running in bottom half\n");
        }

        DECLARE_TASKLET(my_tasklet, my_tasklet_func, 0);

    ③ 工作队列（Workqueue）

        允许任务在内核线程中执行，可以睡眠。

        适用于较长时间的任务（如 I/O 处理、磁盘操作）。

        示例：

        void my_work_handler(struct work_struct *work) {
            printk(KERN_INFO "Workqueue task executing\n");
        }

        DECLARE_WORK(my_work, my_work_handler);

        irqreturn_t my_irq_handler(int irq, void *dev_id) {
            schedule_work(&my_work); // 安排工作队列任务
            return IRQ_HANDLED;
        }

#+begin_src c
      Linux 内核定时器（Kernel Timer）是内核提供的一种定时机制，适用于需要在特定时间点执行任务的场景，
      例如周期性任务、超时处理等。内核定时器的核心数据结构是 struct timer_list，它基于 jiffies 计时，并由 软中断（softirq） 处理。
      1. 基本使用
      1.1 定义定时器

      #include <linux/timer.h>

      struct timer_list my_timer;

      1.2 初始化定时器
      方式 1：使用 timer_setup()

      void my_timer_callback(struct timer_list *timer)
      {
          printk(KERN_INFO "Timer expired!\n");
      }

      void setup_timer(void)
      {
          timer_setup(&my_timer, my_timer_callback, 0);
      }

      方式 2：使用 setup_timer()（较旧，适用于内核 4.15 之前）

      void my_timer_callback(unsigned long data)
      {
          printk(KERN_INFO "Timer expired! Data: %lu\n", data);
      }

      void setup_timer(void)
      {
          setup_timer(&my_timer, my_timer_callback, 0);
      }

      1.3 设置超时时间

      mod_timer() 用于启动或修改定时器：

      void start_timer(unsigned long delay_ms)
      {
          unsigned long delay_jiffies = msecs_to_jiffies(delay_ms);
          mod_timer(&my_timer, jiffies + delay_jiffies);
      }

      其中：

          jiffies：当前内核的滴答数
          msecs_to_jiffies()：将毫秒转换为 jiffies

      1.4 删除定时器

      如果定时器不再需要，必须删除它，避免执行已释放的数据：

      void delete_timer(void)
      {
          del_timer(&my_timer);
      }

          del_timer() 仅删除定时器，不考虑是否正在运行
          del_timer_sync() 会等待定时器回调执行完毕，适用于 SMP（多核）环境

      2. 定时器使用示例

      #include <linux/module.h>
      #include <linux/kernel.h>
      #include <linux/init.h>
      #include <linux/timer.h>
      #include <linux/jiffies.h>

      static struct timer_list my_timer;

      void my_timer_callback(struct timer_list *timer)
      {
          printk(KERN_INFO "Timer expired!\n");
          mod_timer(timer, jiffies + msecs_to_jiffies(1000)); // 继续 1 秒后触发
      }

      static int __init my_module_init(void)
      {
          printk(KERN_INFO "Initializing module\n");

          // 初始化定时器
          timer_setup(&my_timer, my_timer_callback, 0);

          // 设置 1 秒超时
          mod_timer(&my_timer, jiffies + msecs_to_jiffies(1000));

          return 0;
      }

      static void __exit my_module_exit(void)
      {
          del_timer_sync(&my_timer);
          printk(KERN_INFO "Module exiting\n");
      }

      module_init(my_module_init);
      module_exit(my_module_exit);

      MODULE_LICENSE("GPL");
      MODULE_AUTHOR("Example");
      MODULE_DESCRIPTION("Kernel Timer Example");

      3. 注意事项

          内核定时器不是实时的
              Linux 内核调度和其他中断可能会导致定时器误差，适用于非精确定时任务。

          回调函数运行于软中断上下文
              不能睡眠（如 msleep()、mutex_lock()），否则会导致系统崩溃。

          正确删除定时器
              在 module_exit() 或设备移除时，调用 del_timer_sync() 确保安全删除定时器，避免野指针问题。

          替代方案
              高精度定时：hrtimer
              周期性任务：workqueue 或 tasklet
              用户态定时：POSIX 定时器 timer_create()

      4. 适用场景

          超时处理（如 watchdog）
          低精度周期任务（如状态检查）
          软中断调度（如网络协议超时）

      5. 又称为动态定时器

          定时时间到了后自动销毁
          可以在运行时动态设置超时时间和回调函数。
          回调函数在软中断上下文中执行，适合非阻塞、非实时的任务。
          可以随时创建、修改或删除定时器。
          可以实现很多功能，如任务延时、超时重试、周期性任务等。
