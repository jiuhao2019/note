* lf文件管理器使用
lf 常用快捷键，按“日常使用”来记就够了：
** 方向 / 移动
j / ↓        下移
k / ↑        上移
h / ←        返回上级目录
l / →        进入目录 / 打开文件
gg           跳到顶部
G            跳到底部
Ctrl-d       向下半页
Ctrl-u       向上半页
** 文件操作
Enter        打开文件
y            复制
d            删除
r            重命名
p            粘贴

注意：lf 默认的复制/粘贴是“内部剪贴板”，不是系统剪贴板。
** 选择
Space        选择/取消当前文件
v            反选
uv           取消所有选择
** 搜索 / 跳转
/            搜索文件名
n            下一个匹配
N            上一个匹配
f            快速查找
zh           显示/隐藏隐藏文件

不同版本/配置里隐藏文件常见的是 zh，而不是我上一条说的 .。如果你的 lf 是默认配置，可以直接按 zh。
** 目录跳转
gh           回到 home
g/           根目录
** 排序
os           按大小排序
on           按文件名排序
ot           按修改时间排序
oe           按扩展名排序
** 其他
:            输入 lf 命令
!            执行 shell 命令
$            执行 shell 命令并等待
%            执行 shell 命令并保持 lf
q            退出
** 最值得记的其实就是：

flake.nix：
#+begin_src  elisp
{
  description = "Personal GitHub Pages blog";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-26.05";
  };

  outputs = { self, nixpkgs }:
    let
      systems = [
        "x86_64-linux"
        "aarch64-linux"
      ];

      forAllSystems = f:
        nixpkgs.lib.genAttrs systems
          (system: f nixpkgs.legacyPackages.${system});
    in
    {
      devShells = forAllSystems (pkgs: {
        default = pkgs.mkShell {
          packages = with pkgs; [
            ruby
            bundler
          ];

          shellHook = ''
            export BUNDLE_PATH="$PWD/.bundle"
          '';
        };
      });
    };
}
#+end_src
然后：

nix develop

进入后：

** 10. GitHub Actions 自动部署

这是整个系统比较关键的一步。

创建：

mkdir -p .github/workflows
touch .github/workflows/pages.yml

内容：
#+begin_src  yaml
name: Deploy GitHub Pages

on:
  push:
    branches:
      - main

  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Setup Ruby
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: "3.3"
          bundler-cache: true

      - name: Build
        run: bundle exec jekyll build --baseurl "${{ steps.pages.outputs.base_path }}"
        env:
          JEKYLL_ENV: production

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: ./_site

  deploy:
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    runs-on: ubuntu-latest

    needs: build

    steps:
      - name: Deploy
        id: deployment
        uses: actions/deploy-pages@v4
#+end_src
GitHub Pages 的 Actions 工作流本质上就是：

checkout
   ↓
build
   ↓
upload-pages-artifact
   ↓
deploy-pages

这是 GitHub 当前文档推荐的 Pages workflow 模式。

** 13. 最后配置自定义域名

假设以后你买：

example.com

我建议最终使用：

www.example.com

作为主站，同时让：

example.com

跳转过去。

GitHub 官方也建议即使使用 apex domain，也配置 www，因为 www 子域不依赖 GitHub Pages 后端 IP 地址变化，稳定性更好。

在：

GitHub
→ Repository
→ Settings
→ Pages
→ Custom domain

填写：

www.example.com

然后 DNS 提供商添加：
Type: CNAME
Name: www
Value: USERNAME.github.io

如果还要使用：

example.com

则配置 GitHub 给出的 apex DNS 记录。目前 GitHub 文档列出的 IPv4 A 记录为：

185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153

以及对应 IPv6 AAAA 记录。

DNS 生效后：

dig www.example.com

检查。

然后 GitHub Pages 中打开：

Enforce HTTPS

DNS 修改可能需要一段时间传播，GitHub 文档说明最长可能达到 24 小时。

另外，GitHub 建议在正式绑定自定义域之前进行域名验证，以降低域名接管风险。
