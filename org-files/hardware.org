* 直流电机的反向冲击 算浪涌？
#+begin_example
不算严格意义上的“浪涌”，但工程上通常按浪涌/瞬态过压来处理。

需要区分几个概念：

1）标准“浪涌”
一般指电源线上外部引入的高能量瞬态，例如雷击或开关操作，对应测试如 IEC 61000-4-5。特点是：

能量大（kV级）
来自外部电网
波形标准化（1.2/50µs）

2）直流电机反向冲击
本质是电机绕组电感产生的反电动势（Back EMF）：

断电、刹车、反转时产生
能量来自电机自身储能（L·I²）
电压尖峰可很高，但能量相对“浪涌”小
属于开关瞬态 / 感性负载尖峰

3）工程归类
在EMC/可靠性设计里，通常归为：

EFT（快速瞬变）的一种来源（非标准源）
或“浪涌类瞬态”统一处理（因为对器件破坏机理类似）

结论

定义上：不是标准浪涌
设计上：必须按浪涌/瞬态来防护

常见防护手段（你这个24V电机场景）：

续流二极管（最基础）
TVS（二级保护，抑制高压尖峰）
RC snubber（减缓dv/dt）
MOS管选型留裕量（Vds ≥ 2~3倍母线电压）
布局：回流路径短、地弹控制

如果是H桥或反转场景，需要额外注意：

反向时不是简单“续流”，而是能量回灌电源
电源端也可能被抬高（导致系统整体过压）

如果你需要，可以把你的电机驱动拓扑（MOS/继电器/H桥）给出来，可以直接帮你算一个最坏尖峰电压范围。
#+end_example
* 电磁兼容（EMC）
** 概念
电磁兼容（EMC）：设备在电磁环境中既不干扰别人，也不被干扰
电磁干扰（EMI）：设备对外发射的干扰
电磁抗扰度（EMS）：设备抵抗外界干扰的能力

关系可以理解为：
EMC = EMI（发射） + EMS（抗扰）
** 电磁抗扰（EMS）
电磁抗扰度指设备在受到外界干扰时，是否还能正常工作，不死机、不误动作、不损坏。
*** 典型干扰类型：
**** 静电放电（ESD）
人体放电
接触/空气放电
瞬间高压（kV级）
**** 电快速瞬变脉冲群（EFT/Burst）
继电器、电机开关产生
高频脉冲串
**** 浪涌（Surge）
雷击、电网切换
高能量、低频瞬态
标准：IEC 61000-4-5
**** 传导抗扰
电源线上叠加干扰信号
标准：IEC 61000-4-6
**** 辐射抗扰
空间电磁波干扰（如无线设备）
标准：IEC 61000-4-3

*** CTR

**** 规格书里 [ 最小-典型-最大 ] 的CTR
#+begin_example
光耦 CTR（Current Transfer Ratio，电流传输比）如果规格书只给：

CTR min（最小）
CTR typ（典型）
CTR max（最大）

但是 typ 没有给数值，设计时不要自己猜典型值，应该按 最小 CTR 设计。

原因：

CTR 离散性很大，而且会随：

LED 电流 IF
温度
老化
VCE 电压
批次

变化。

如果是驱动 MOS 管、继电器、逻辑输入：

一般还要留裕量，比如：

实际需要光耦输出 1mA：

不要设计：
1mA = CTR × IF

而应设计：
2mA = CTR × IF

这样温度、老化后还能工作。

所以结论：

CTR典型没有值 → 按 CTR最小值设计
CTR最大值只用于判断LED电流是否过大
不建议用典型CTR做量产设计
#+end_example

**** 光耦输出三极管进入饱和状态的条件是：
#+begin_example

** tPLH、tPHL
#+begin_src C
这两个是传播延迟。

光耦不是：

输入变化
    ↓
输出立即变化

而是：

输入变化
    ↓
LED 发光
    ↓
光接收
    ↓
内部电路处理
    ↓
输出变化

所以存在延迟。

tPLH

Propagation Delay, Low → High

表示：

输入导致输出从 LOW → HIGH 所需要的时间。

例如：

tPLH = 100 ns
tPHL

Propagation Delay, High → Low

表示：

输入导致输出从 HIGH → LOW 所需要的时间。

例如：

tPHL = 80 ns
#+end_src
** tr、tf
#+begin_src C
这是输出信号的上升时间和下降时间。

tr：

输出从 LOW 上升到 HIGH 所需要的时间。

通常定义类似：

10% → 90%

tf：

输出从 HIGH 下降到 LOW 所需要的时间。

通常类似：

90% → 10%

例如：

tr = 20 ns
tf = 15 ns

表示输出边沿比较快。

这个和 tPLH/tPHL 不一样：

tPLH / tPHL
    ↓
“什么时候开始发生变化？”

tr / tf
    ↓
“开始变化以后，变化得有多快？”
#+end_src

* 直流电机过流保护
可以把整个“电机电流采集 + 滤波 + 保护”整理成下面这套逻辑。对于你当前 STM32 + 5 路 ADC DMA 的方案，我建议先保持简单。
** 1. ADC 持续采样
ADC 12 MHz，5 通道，239.5 cycles：

T_{单通道}=(239.5+12.5)/12M=21\mu s

5 路扫描： T_{scan}=105\mu s

所以每个通道约 9.52 kHz。

DMA 每得到一组数据，中断里只做累加：
#+begin_src C
sum[ch] += adc_dma[ch];
cnt[ch]++;
#+end_src
不要在这里做 IIR、浮点运算或者复杂的保护逻辑。
** 2. 电流任务：建议 10 ms
*** 每 10 ms 处理一次：
#+begin_src C
raw_avg = sum / cnt;

sum = 0;
cnt = 0;
#+end_src

10 ms 内每个通道大约有： 10ms / 105\mu s \approx 95 个样本。

所以 raw_avg 本身已经是一个比较稳定的电流值。

然后转换成实际电流：
#+begin_src C
current_avg = adc_to_current(raw_avg);
#+end_src

这里的 current_avg 是后续过流/堵转判断的主要依据。
** 3. 再做一阶 IIR
current_filter += alpha * (current_avg - current_filter);

例如：
alpha = 0.1f;

于是有两个电流：
current_avg      // 10ms平均，响应快
current_filter   // IIR后，稳定

用途不要混：
current_avg
    → 过流判断
    → 堵转判断

current_filter
    → 电流显示
    → 状态监测
    → 需要稳定电流值的控制逻辑

保护逻辑优先使用 current_avg，不要等 current_filter 慢慢升上去。
** 4. 电机启动时
电机启动电流天然比较大，所以：
STOP
  ↓
启动
  ↓
软启动阶段
PWM逐渐增加
  │
  ├── 极端过流 → 停止
  │
  └── 普通过流暂不判断
  ↓
软启动完成
  ↓
正常运行
  │
  ├── 极端过流
  └── 普通过流/堵转

也就是：
#+begin_src C
if (current_avg > CURRENT_CRITICAL)
{
    motor_stop();
}
else if (soft_start_finished)
{
    /* 普通过流判断 */
}
#+end_src

CURRENT_CRITICAL 是保护硬件的极端异常阈值，软启动也不能关闭。
** 5. 正常运行后的过流不要一超就停
建议加入持续时间：
#+begin_src C
if (current_avg > CURRENT_OVER)
{
    over_cnt++;

    if (over_cnt >= 5)
    {
        motor_stop();
    }
}
else
{
    over_cnt = 0;
}
#+end_src

任务周期 10 ms：
1 次 = 10 ms
3 次 = 30 ms
5 次 = 50 ms
10次 = 100 ms
20次 = 200 ms

例如设置：
#define CURRENT_OVER_TIME_MS     100

那么：
#define CURRENT_OVER_CNT \
    (CURRENT_OVER_TIME_MS / 10)

持续超过阈值 100 ms 才认为过流/堵转。
** 6. 最终建议的完整数据链
你的系统可以简化成：
ADC 5通道连续扫描
        │
        │ 每通道约 9.52kHz
        ↓
DMA
        │
        ↓
sum += adc
cnt++
        │
        │ 每10ms
        ↓
ADC平均值
sum / cnt
        │
        ├──────────────→ current_avg
        │                    │
        │                    ├─ 极端过流
        │                    │   → 立即停
        │                    │
        │                    └─ 软启动完成
        │                         ↓
        │                    普通过流
        │                    持续50~200ms
        │                         ↓
        │                       停机
        │
        ↓
一阶IIR
alpha = 0.1~0.2
        │
        ↓
current_filter
        │
        └─ 显示/状态/控制

因此代码层面最好明确维护：
typedef struct
{
    uint32_t sum;
    uint32_t cnt;

    float current_avg;
    float current_filter;

    uint16_t over_cnt;

} motor_current_t;

** 核心原则就是一句：
                           - ADC 高频采集 → 10 ms 窗口平均 → current_avg 做保护 → IIR 得到 current_filter 做稳定电流值；软启动期间只保留极端过流，软启动完成后再开启带时间确认的普通堵转/过流保护。
                           - 对于普通直流电机堵转保护，我会先从 10 ms任务 + 100 ms连续过流确认 开始调，然后根据实际堵转波形调整阈值和确认时间。
